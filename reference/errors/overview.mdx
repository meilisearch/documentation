Meilisearch exposes two HTTP APIs, and both report failures with a standard HTTP status code and a JSON body. The body is shaped differently in each API, so read the section matching the API you are calling.

For the list of every code the two APIs can return, see [error codes](/reference/errors/error_codes).

## Status codes

### Meilisearch API

The [Meilisearch API](/reference/api/authorization) uses the following standard HTTP codes for a successful or failed API request:

| Status code | Description                                                                                |
| :---------- | :----------------------------------------------------------------------------------------- |
| 200         | ✅ **Ok** Everything worked as expected.                                                   |
| 201         | ✅ **Created** The resource has been created (synchronous)                                 |
| 202         | ✅  **Accepted** The task has been added to the queue (asynchronous)                       |
| 204         | ✅ **No Content** The resource has been deleted or no content has been returned            |
| 205         | ✅ **Reset Content** All the resources have been deleted                                   |
| 400         | ❌ **Bad Request** The request was unacceptable, often due to missing a required parameter |
| 401         | ❌ **Unauthorized** No valid API key provided                                              |
| 403         | ❌ **Forbidden** The API key doesn't have the permissions to perform the request           |
| 404         | ❌ **Not Found** The requested resource doesn't exist                                      |

### Management API

The [Management API](/reference/management-api/authentication) uses the following standard HTTP codes:

| Status code | Description                                                                                     |
| :---------- | :---------------------------------------------------------------------------------------------- |
| 200         | ✅ **Ok** Everything worked as expected.                                                        |
| 201         | ✅ **Created** The resource has been created                                                    |
| 202         | ✅ **Accepted** The operation has been accepted and is running in the background                |
| 204         | ✅ **No Content** The resource has been deleted or no content has been returned                 |
| 400         | ❌ **Bad Request** The request was unacceptable, often due to missing a required parameter      |
| 401         | ❌ **Unauthorized** No valid personal access token provided                                     |
| 403         | ❌ **Forbidden** The token doesn't have the permissions to perform the request, or a plan limit has been reached |
| 404         | ❌ **Not Found** The requested resource doesn't exist                                           |
| 409         | ❌ **Conflict** The resource conflicts with an existing one, such as a duplicate project name   |
| 422         | ❌ **Unprocessable Content** The request is well-formed but was rejected, usually after validation |
| 423         | ❌ **Locked** The resource is temporarily unavailable, such as a project that is not running    |
| 500         | ❌ **Internal Server Error** Something went wrong on the Meilisearch Cloud side                 |

## Error types

Only the Meilisearch API returns an error type. All detailed task responses contain an [`error`](/reference/api/tasks/get-task) field. When a task fails, it is always accompanied by a JSON-formatted error response. Meilisearch errors can be of one of the following types:

| Type                  | Description                                                                                                                                                                                     |
| :-------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`invalid_request`** | This is due to an error in the user input. It is accompanied by the HTTP code `4xx`                                                                                                             |
| **`internal`**        | This is due to machine or configuration constraints. It is accompanied by the HTTP code `5xx`                                                                                                   |
| **`auth`**            | This type of error is related to authentication and authorization. It is accompanied by the HTTP code `4xx`                                                                                     |
| **`system`**          | This indicates your system has reached or exceeded its limit for disk size, index size, open files, or the database doesn't have read or write access. It is accompanied by the HTTP code `5xx` |

The Management API does not categorize its errors. Use the [error code](/reference/errors/error_codes#management-api-error-codes) and the HTTP status code instead.

## Error format

### Meilisearch API

```json
{
  "message": "Index `movies` not found.",
  "code": "index_not_found",
  "type": "invalid_request",
  "link": "https://docs.meilisearch.com/errors#index_not_found"
}
```

| Field         | Description                                       |
| :------------ | :------------------------------------------------ |
| **`message`** | Human-readable description of the error           |
| **`code`**    | [Error code](/reference/errors/error_codes#meilisearch-api-error-codes) |
| **`type`**    | [Type](#error-types) of error returned            |
| **`link`**    | Link to the relevant section of the documentation |

### Management API

```json
{
  "status": "error",
  "code": "project_not_found",
  "message": {
    "title": "Project not found",
    "description": "Project does not exist"
  }
}
```

| Field                     | Description                                                                   |
| :------------------------ | :---------------------------------------------------------------------------- |
| **`status`**              | Always `error` in an error response                                           |
| **`code`**                | [Error code](/reference/errors/error_codes#management-api-error-codes)        |
| **`message.title`**       | Short human-readable summary of the error                                     |
| **`message.description`** | Longer description of the error. It may include details specific to your request, and it is empty for some error codes |
