The Management API reports a failed request with a standard HTTP status code and a JSON body describing what went wrong. The body always contains a `code` field identifying the error. Branch on that `code` rather than on the human-readable `message`, which may change between releases.

The Management API is only available on Meilisearch Cloud. The [Meilisearch API](/reference/api/authorization) reports its errors separately, in the same format. See [Meilisearch API errors](/reference/errors).

## Status codes

The Management API uses the following standard HTTP codes for a successful or failed API request:

| Status code | Description                                                                                                     |
| :---------- | :--------------------------------------------------------------------------------------------------------------- |
| 200         | ✅ **Ok** Everything worked as expected.                                                                        |
| 201         | ✅ **Created** The resource has been created                                                                    |
| 202         | ✅ **Accepted** The operation has been accepted and is running in the background                                |
| 204         | ✅ **No Content** The resource has been deleted or no content has been returned                                 |
| 400         | ❌ **Bad Request** The request was unacceptable, often due to a missing or malformed parameter                  |
| 401         | ❌ **Unauthorized** No valid personal access token provided                                                     |
| 403         | ❌ **Forbidden** The token doesn't have the permissions to perform the request, or a plan limit has been reached |
| 404         | ❌ **Not Found** The requested resource doesn't exist                                                           |
| 409         | ❌ **Conflict** The resource conflicts with an existing one, such as a duplicate project name                   |
| 422         | ❌ **Unprocessable Content** The request is well-formed but was rejected, usually after validation              |
| 423         | ❌ **Locked** The resource is temporarily unavailable, such as a project that is not running                    |
| 500         | ❌ **Internal Server Error** Something went wrong on the Meilisearch Cloud side                                 |

## Error types

Every error response carries a `type` field describing the broad category of the failure. It is derived from the HTTP status code:

| Type                  | Description                                                                              |
| :-------------------- | :---------------------------------------------------------------------------------------- |
| **`auth`**            | The personal access token is missing or invalid. It is accompanied by the HTTP code `401` |
| **`invalid_request`** | The request was rejected, usually because of its input. It is accompanied by any other HTTP code `4xx` |
| **`internal`**        | Something went wrong on the Meilisearch Cloud side. It is accompanied by the HTTP code `5xx` |

## Error format

```json
{
  "message": "Project not found",
  "code": "project_not_found",
  "type": "invalid_request",
  "link": "https://www.meilisearch.com/docs/reference/management-api-errors#project_not_found"
}
```

| Field         | Description                                       |
| :------------ | :------------------------------------------------ |
| **`message`** | Human-readable description of the error           |
| **`code`**    | [Error code](#error-codes)                        |
| **`type`**    | [Type](#error-types) of error returned            |
| **`link`**    | Link to the relevant section of the documentation |

### Validation errors

When a request fails validation, the body carries an additional `errors` array with one entry per rejected field:

```json
{
  "message": "Validation error",
  "code": "validation_error",
  "type": "invalid_request",
  "link": "https://www.meilisearch.com/docs/reference/management-api-errors#validation_error",
  "errors": [
    {
      "field": "teamId",
      "code": "blank",
      "message": "Team can't be blank"
    }
  ]
}
```

| Field                | Description                                                 |
| :------------------- | :----------------------------------------------------------- |
| **`errors[].field`** | Name of the rejected field, in camelCase as in the request   |
| **`errors[].code`**  | Stable identifier of the validation failure                  |
| **`errors[].message`** | Human-readable description of the validation failure       |
