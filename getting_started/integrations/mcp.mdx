The [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) lets AI agents and LLM clients call external tools. Meilisearch ships a native MCP server at the `POST /mcp` route so any MCP-compatible client can search your indexes directly.

The server exposes four read-only, search-focused tools. It does not expose index, document, settings, or API key management. Use the Meilisearch API or the Cloud UI for those operations.

## Requirements

- A Meilisearch project running v1.54 or later
- Your project's host URL and an API key
- An MCP client that supports remote HTTP servers, such as Claude Code, Codex, or Cursor

## Connect an MCP client

Register `https://your-host/mcp` as a remote MCP server and send your Meilisearch API key as a bearer token in the `Authorization` header. There is no OAuth flow: the API key is the only credential required.

```json
{
  "mcpServers": {
    "meilisearch": {
      "url": "https://your-host/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}
```

The exact configuration format depends on your client. Two common examples:

<CodeGroup>

```bash Claude Code
claude mcp add --transport http meilisearch https://your-host/mcp \
  --header "Authorization: Bearer YOUR_API_KEY"
```

```toml Codex
[mcp_servers.meilisearch]
url = "https://your-host/mcp"
http_headers = { "Authorization" = "Bearer YOUR_API_KEY" }
```

</CodeGroup>

Consult your client's documentation for the exact syntax it expects for remote MCP servers with custom headers.

## Available tools

| Tool | Wraps | Description |
|------|-------|-------------|
| `listIndexes` | `GET /indexes` | Lists available indexes. Accepts `offset` and `limit` |
| `describeIndex` | `POST /indexes/{indexUid}/documents/fetch` | Returns up to 5 sample documents from an index, so an agent can understand its shape and purpose |
| `searchInIndexes` | `POST /multi-search` | Searches one or more indexes at once. Accepts the full multi-search body: query, filter, sort, facets, hybrid search, and federated results |
| `facetSearch` | `POST /indexes/{indexUid}/facet-search` | Searches facet values for an index. Accepts the same body as facet search, plus a required `indexUid` |

The server recommends agents call `listIndexes`, then `describeIndex`, then `searchInIndexes`, in that order, so the agent understands what data is available before searching it.

There is no single-index search tool. `searchInIndexes` covers single-index search too: pass one index in the `indexUid` list of the multi-search body.

<Note>
`describeIndex` only returns sample documents. It does not return an index's settings or configured embedders.
</Note>

## Authentication and permissions

Every tool call runs with the same permissions as the API key or [tenant token](/capabilities/security/getting_started) you provide in the `Authorization` header. A search-only key can only retrieve indexes and documents that the key allows. There is no separate permission model for MCP: whatever your key can do through the search API, it can do through MCP, and nothing more.

## What you can't do with MCP

The MCP server only exposes search-related tools. It cannot create or delete indexes, add or edit documents, change index settings, manage API keys, or check tasks or instance health. If you ask an LLM client to perform one of these actions, it may claim success without actually doing anything, since LLMs tend to agree with requests even when no matching tool exists. Use the Meilisearch API or the Cloud UI for anything beyond search.

## Troubleshooting

If your MCP client can't connect or calls fail:

- Confirm the `mcpRoute` experimental feature is enabled on your project
- Confirm your API key or tenant token is valid and has search permissions on the indexes you're querying
- Confirm your client supports remote MCP servers over HTTP, rather than only local stdio servers
- Check your client's own logs for the raw error returned by the `/mcp` route

<Accordion title="Legacy: the meilisearch-mcp Python server">
Before Meilisearch shipped a native MCP route, [`meilisearch-mcp`](https://github.com/meilisearch/meilisearch-mcp) was a separate Python package that ran as a local stdio process alongside desktop clients like Claude Desktop. It exposed a much larger, management-oriented tool set: creating and deleting indexes, adding documents, updating settings, managing API keys, and checking tasks and instance health, in addition to search.

This package is now archived in favor of the built-in `/mcp` route described on this page. If you still rely on the Python server, consult its [README](https://github.com/meilisearch/meilisearch-mcp) for installation and configuration instructions. It is no longer actively maintained and is not compatible with the guidance above.
</Accordion>
