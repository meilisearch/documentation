Crawl a site by reading `robots.txt` first, expanding the sitemap into a URL list, fetching each page one at a time with a delay between requests, and writing one record per page section rather than per page. Use the sitemap as the source of truth whenever the site publishes one, because it gives you a complete URL list and a `lastmod` date per URL, and fall back to following links only for the pages the sitemap misses. On a recrawl, send conditional requests so unchanged pages cost a `304` instead of a download, and delete records for URLs that have disappeared. Meilisearch Cloud ships a [built-in crawler](/getting_started/features#cloud-features) that does all of this for you; everything below applies when you run your own.

## Sitemap-driven or link discovery

These are not alternatives so much as a primary and a fallback.

**Start from the sitemap.** `robots.txt` usually names it with a `Sitemap:` line, and `/sitemap.xml` is the conventional location otherwise. A sitemap index points at child sitemaps, so the parse is recursive. What you get is a flat list of canonical URLs, each optionally carrying `lastmod`, which is the single most useful field in the whole crawl: it tells you which pages to refetch without fetching them first.

**Follow links for the gaps.** Sitemaps go stale, are generated by plugins that skip content types, and often omit anything behind a filter. Link discovery catches those, at the cost of a frontier queue, same-origin checks, a depth limit, and URL normalization. Normalize before enqueuing: drop the fragment, strip tracking parameters, sort the remaining query parameters, and settle on one trailing-slash convention. Without that, `/pricing`, `/pricing/`, and `/pricing?utm_source=x` are three crawls of one page.

**Skip listing pages either way.** Tag archives, paginated indexes, and category feeds are navigation. Indexing them produces records that are lists of titles, and those outrank the articles they link to.

## Respecting robots.txt and rate limits

`robots.txt` is a small file with real consequences, and the parsing rules are less obvious than they look.

- **Only one user-agent group applies.** A crawler obeys the most specific group matching its own token, and falls back to `User-agent: *` only when no specific group exists. Rules are not merged across groups.
- **The longest matching rule wins.** When both an `Allow` and a `Disallow` rule match a path, the longer pattern takes precedence, so `Allow: /docs/public/` beats `Disallow: /docs/`.
- **`Crawl-delay` is not part of the standard.** It is widely published and widely honored, but it is not in the Robots Exclusion Protocol specification, and some major crawlers ignore it in favor of their own scheduling {/* VERIFY: which crawlers document ignoring Crawl-delay, and whether RFC 9309 mentions it at all */}. Honor it when present, and pick your own default when it is not.
- **A missing `robots.txt` is permission, a `5xx` is not.** A `404` means no restrictions. A server error means unknown, so back off rather than crawl freely.

For rate limits, one request at a time with a delay of about one second is a safe starting point for a site you do not own, and still covers a few thousand pages overnight. Send a descriptive `User-Agent` with a contact URL so an operator can reach you instead of blocking you. Treat `429` and `503` as instructions: read `Retry-After`, sleep that long, and retry once. On a second `429`, double the delay for the rest of the run.

## Turning each page into records

One page is almost never one good search record. Strip the navigation, header, footer, and sidebar, split what remains on its heading hierarchy, and emit one document per section carrying the page URL plus the section anchor so a result deep-links to the right place. [How to chunk web pages](/guides/chunk-web-pages) covers the extraction rules in detail.

Whatever the split, every record should carry the fields the crawl itself produces: the canonical `page_url` for grouping, a `content_hash` for change detection, and a `crawled_at` timestamp so you can find records the last run failed to refresh. Hash the URL into the primary key, since primary keys accept only `a-z`, `A-Z`, `0-9`, `-`, and `_`.

Set [`distinctAttribute`](/capabilities/full_text_search/how_to/configure_distinct_attribute) to `page_url`. Meilisearch then returns at most one document per distinct value, so a page whose six sections all match shows up once, pointing at the section that matched best.

## Detecting duplicate and near-duplicate pages

Exact duplicates come from URL variants and are best solved at the URL level: read `link rel="canonical"` from the page and use it as the grouping key, so print views, `?ref=` variants, and session-id URLs collapse into one record set.

Near-duplicates are harder: localized variants sharing an English body, versioned documentation where `/v2/` and `/v3/` differ in three paragraphs, or paginated content repeating an introduction. Two cheap defenses go a long way:

- **Hash the extracted main text**, not the raw HTML, after collapsing whitespace and lowercasing. Identical bodies then collide on the hash and you index the first one.
- **For genuinely near-identical pages**, compare shingles: split the normalized text into overlapping word windows, hash each window, and compute the overlap between two pages. Above roughly 90% overlap, keep the canonical one and drop the rest. Doing this exactly across a large crawl is expensive, which is why production crawlers use a similarity sketch such as SimHash or MinHash rather than full comparison {/* VERIFY: typical shingle width and similarity threshold used in production deduplication */}.

If you would rather not drop near-duplicates at crawl time, index them all and set `distinctAttribute` to a field holding the content hash, which suppresses them at query time instead.

## Choosing a recrawl cadence

Recrawling everything nightly quietly becomes a problem: it spends full bandwidth, rewrites documents that did not change, and adds indexing load for nothing.

- **Let the site tell you.** Compare the sitemap's `lastmod` against your stored `crawled_at` and fetch only what moved. This alone usually cuts a recrawl by an order of magnitude.
- **Send conditional requests.** Store the `ETag` and `Last-Modified` of every page and replay them as `If-None-Match` and `If-Modified-Since`. A `304 Not Modified` costs one round trip and no parsing.
- **Split the site by volatility.** Pricing pages and changelogs change weekly or faster, reference documentation rarely. Two schedules, hourly for a short list and weekly for the rest, beat one compromise interval.
- **Trigger on deploy where you can.** For a site you control, running the crawl from CI on publish is more accurate than any interval.
- **Handle deletions explicitly.** Nothing in an incremental crawl reports a removed page. Either record which URLs the run saw and delete the rest by filter, or crawl into a fresh index and [swap it in](/reference/api/indexes/swap-indexes) once the run finishes, which also gives you an atomic cutover.

## A complete working crawler

This script reads `robots.txt`, expands the sitemap, falls back to link discovery, rate limits itself, skips unchanged and duplicate pages, chunks each page on headings, and indexes the result.

```javascript
// npm install cheerio meilisearch      (Node 18+ for global fetch)
//
// export MEILISEARCH_URL="https://ms-example.meilisearch.io"
// export MEILISEARCH_KEY="$MEILISEARCH_ADMIN_KEY"

import { createHash } from 'node:crypto'
import { setTimeout as sleep } from 'node:timers/promises'
import * as cheerio from 'cheerio'
import { Meilisearch } from 'meilisearch'

const ORIGIN = 'https://example.com'
const START = `${ORIGIN}/docs/`
const AGENT = 'ExampleBot/1.0 (+https://example.com/bot)'
const DEFAULT_DELAY = 1000
const MAX_PAGES = 500
const CHROME = 'nav, header, footer, aside, script, style, noscript, .sidebar, .toc'

const sha1 = (s) => createHash('sha1').update(s).digest('hex')
const flatten = (s) => s.toLowerCase().replace(/\s+/g, ' ').trim()

// Persist this between runs (a JSON file or a table) to make recrawls incremental.
const state = new Map()   // url -> { etag, lastModified, contentHash }

function normalize(href, base) {
  const u = new URL(href, base)
  u.hash = ''
  for (const key of [...u.searchParams.keys()]) {
    if (key.startsWith('utm_') || key === 'ref' || key === 'fbclid') u.searchParams.delete(key)
  }
  u.searchParams.sort()
  u.pathname = u.pathname.replace(/\/+$/, '') || '/'
  return u.toString()
}

async function readRobots() {
  const rules = { allow: [], disallow: [], delay: DEFAULT_DELAY, sitemaps: [] }
  const res = await fetch(`${ORIGIN}/robots.txt`, { headers: { 'user-agent': AGENT } })
  if (res.status >= 500) throw new Error('robots.txt unavailable, not crawling')
  if (!res.ok) return rules                       // 404 means no restrictions
  let applies = false
  for (const raw of (await res.text()).split('\n')) {
    const [field, ...rest] = raw.split('#')[0].split(':')
    const value = rest.join(':').trim()
    if (!value) continue
    switch (field.trim().toLowerCase()) {
      case 'user-agent': applies = value === '*' || AGENT.toLowerCase().startsWith(value.toLowerCase()); break
      case 'allow': if (applies) rules.allow.push(value); break
      case 'disallow': if (applies) rules.disallow.push(value); break
      case 'crawl-delay': if (applies) rules.delay = Number(value) * 1000; break
      case 'sitemap': rules.sitemaps.push(value); break
    }
  }
  return rules
}

function permitted(url, rules) {
  const path = new URL(url).pathname
  const longest = (list) =>
    list.filter((r) => path.startsWith(r)).sort((a, b) => b.length - a.length)[0] ?? ''
  const deny = longest(rules.disallow)
  return !deny || longest(rules.allow).length >= deny.length   // longest rule wins
}

async function readSitemap(url, seen = new Set()) {
  if (seen.has(url)) return []
  seen.add(url)
  const res = await fetch(url, { headers: { 'user-agent': AGENT } })
  if (!res.ok) return []
  const $ = cheerio.load(await res.text(), { xmlMode: true })
  const children = $('sitemapindex > sitemap > loc').map((_, el) => $(el).text().trim()).get()
  if (children.length) {
    const out = []
    for (const child of children) out.push(...(await readSitemap(child, seen)))
    return out
  }
  return $('urlset > url').map((_, el) => ({
    url: normalize($(el).find('loc').text().trim(), ORIGIN),
    lastmod: $(el).find('lastmod').text().trim() || null,
  })).get()
}

async function fetchPage(url) {
  const cached = state.get(url) ?? {}
  const headers = { 'user-agent': AGENT }
  if (cached.etag) headers['if-none-match'] = cached.etag
  if (cached.lastModified) headers['if-modified-since'] = cached.lastModified
  let res = await fetch(url, { headers })
  if (res.status === 429 || res.status === 503) {
    await sleep(Number(res.headers.get('retry-after') ?? 30) * 1000)
    res = await fetch(url, { headers })
  }
  return res
}

function chunkPage(html, requestedUrl) {
  const $ = cheerio.load(html)
  const pageUrl = normalize($('link[rel="canonical"]').attr('href') || requestedUrl, requestedUrl)
  const title = ($('h1').first().text() || $('title').text()).trim()
  $(CHROME).remove()
  const root = $('main').first().length ? $('main').first() : $('body')

  const sections = []
  let current = { heading: title, anchor: '', text: [] }
  root.find('h2, h3, p, li, pre, td').each((_, el) => {
    const text = $(el).text().replace(/\s+/g, ' ').trim()
    if (!text) return
    if (el.tagName === 'h2' || el.tagName === 'h3') {
      sections.push(current)
      current = { heading: text, anchor: $(el).attr('id') ?? '', text: [] }
    } else current.text.push(text)
  })
  sections.push(current)

  const body = flatten(sections.flatMap((s) => s.text).join(' '))
  const documents = sections
    .filter((s) => s.text.join(' ').split(' ').length >= 20)   // skip thin sections
    .map((s, i) => ({
      id: sha1(`${pageUrl}#${i}:${s.anchor}`),   // index keeps anchorless sections distinct
      url: s.anchor ? `${pageUrl}#${s.anchor}` : pageUrl,
      page_url: pageUrl,
      page_title: title,
      heading_path: [title, s.heading].filter(Boolean).join(' > '),
      content: s.text.join(' '),
      content_hash: sha1(body),
      crawled_at: Math.floor(Date.now() / 1000),
    }))
  return { pageUrl, documents, bodyHash: sha1(body) }
}

const rules = await readRobots()
const sitemapUrls = (await Promise.all(
  (rules.sitemaps.length ? rules.sitemaps : [`${ORIGIN}/sitemap.xml`]).map((s) => readSitemap(s)),
)).flat()

const queue = sitemapUrls.length ? sitemapUrls.map((e) => e.url) : [normalize(START, ORIGIN)]
const queued = new Set(queue)
const seenBodies = new Set()
const documents = []
const liveUrls = []

while (queue.length && liveUrls.length < MAX_PAGES) {
  const url = queue.shift()
  if (!url.startsWith(ORIGIN) || !permitted(url, rules)) continue

  const res = await fetchPage(url)
  await sleep(rules.delay)                         // politeness delay, every request
  if (res.status === 304) { liveUrls.push(url); continue }
  if (!res.ok || !res.headers.get('content-type')?.includes('text/html')) continue

  const html = await res.text()
  const { pageUrl, documents: docs, bodyHash } = chunkPage(html, url)
  liveUrls.push(pageUrl)
  state.set(url, {
    etag: res.headers.get('etag'),
    lastModified: res.headers.get('last-modified'),
    contentHash: bodyHash,
  })

  if (seenBodies.has(bodyHash)) continue           // duplicate body, already indexed
  seenBodies.add(bodyHash)
  documents.push(...docs)

  if (!sitemapUrls.length) {                       // link discovery fallback
    const $ = cheerio.load(html)
    $('a[href]').each((_, el) => {
      const next = normalize($(el).attr('href'), url)
      if (next.startsWith(ORIGIN) && !queued.has(next)) { queued.add(next); queue.push(next) }
    })
  }
}

const client = new Meilisearch({
  host: process.env.MEILISEARCH_URL,
  apiKey: process.env.MEILISEARCH_KEY,
})
const index = client.index('site')

await client.waitForTask((await index.updateSettings({
  searchableAttributes: ['page_title', 'heading_path', 'content'],
  filterableAttributes: ['page_url', 'crawled_at'],
  distinctAttribute: 'page_url',
})).taskUid)

for (let i = 0; i < documents.length; i += 1000) {
  await client.waitForTask((await index.addDocuments(documents.slice(i, i + 1000))).taskUid)
}
console.log(`${documents.length} records from ${liveUrls.length} pages`)

const results = await index.search('rate limits', { attributesToCrop: ['content'], cropLength: 30 })
for (const hit of results.hits) console.log(`${hit.heading_path}\n  ${hit.url}`)
```

To remove pages deleted since the last run, keep a `crawl_id` field on every record and delete by filter where `crawl_id` is not the current one, using the [delete by filter](/capabilities/indexing/how_to/delete_documents_at_scale) endpoint.

## Limits and constraints

- **65,535 positions per attribute.** Text past that point is [silently ignored](/resources/help/known_limitations#maximum-number-of-words-per-attribute). Hard separators such as commas each consume eight positions, so a long page dumped into one field loses its tail. Chunking avoids this.
- **Primary keys** must be integers or strings of `a-z`, `A-Z`, `0-9`, `-`, and `_`, and at most **511 bytes**. A URL is never a valid primary key, so hash it.
- **Individual `filterableAttributes` values are capped at 468 bytes**, which long URLs used as filter values can exceed.
- **One `distinctAttribute` per index**, and changing it reindexes everything, so set it before the first crawl.
- **Payload defaults to 100MB per request**, and uploads through the Meilisearch Cloud interface are capped at **20MB**, so index [from a script](/capabilities/indexing/how_to/import_large_datasets) rather than the interface for a real crawl.
- **A sitemap file holds at most 50,000 URLs and 50MB uncompressed**, per the sitemaps specification. Larger sites publish a sitemap index pointing at several files, which is why the parse has to recurse {/* VERIFY: current sitemaps.org limits, which were raised from 10MB at one point */}.
- **Meilisearch does not crawl, fetch, or parse HTML.** The engine indexes documents you send it. The Cloud crawler and [docs-scraper](/getting_started/instant_meilisearch/docsearch) are separate tools that sit in front of it.
